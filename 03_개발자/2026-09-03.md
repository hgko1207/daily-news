## 3. Show HN: 48GB Mac에서 104GB Qwen3.8-Flash-Next를 ~12 tok/s로 구동 (182 points)

**요약**
`slotstream`이라는 프로젝트로, 물리 메모리(48GB)의 두 배가 넘는 104GB 모델을 맥에서 초당 약 12토큰으로 실행하는 데 성공한 사례. 함께 상위권에 오른 "My local model setup on an M4 Pro Mac Mini"(118 points)도 로컬 LLM 셋업을 다룬다.

**왜 눈여겨볼지**
로컬 모델 실행이 "가능은 하지만 비현실적"에서 "메모리 제약을 우회하는 엔지니어링 문제"로 넘어가고 있다. API 비용, 데이터 프라이버시, 오프라인 개발 환경이 중요한 프로젝트라면 실용적 선택지가 하나 더 생긴 셈이다. 12 tok/s는 대화형으로는 느리지만 배치 작업에는 충분하다.

## 5. AI 코딩 도구 지형 — Claude Code · Cursor · Copilot

**요약**
2026년 AI 코딩 도구 시장은 '통합 IDE 코파일럿'과 '자율 터미널 에이전트'라는 두 철학으로 갈렸다. Cursor는 2026년 3월 기준 ARR 20억 달러를 기록했고, GitHub Copilot은 포춘 100대 기업 중 90% 이상이 채택 중이다(지멘스는 약 3만 명 개발자가 사용). Claude Code의 Opus 4.6 모델은 SWE-bench 80.8%를 기록했다.
※ 위 수치는 2차 매체·블로그 기준 인용이므로 참고 지표로만 볼 것.

**왜 눈여겨볼지**
두 철학은 우열이 아니라 작업 유형의 차이에 가깝다. 코드를 읽으며 조금씩 고치는 작업은 IDE 코파일럿이, 명세를 주고 여러 파일을 한 번에 바꾸는 작업은 터미널 에이전트가 유리하다. 하나만 쓰기보다 작업에 따라 나눠 쓰는 편이 실무에서는 효율적이다.
