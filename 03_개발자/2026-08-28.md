## 1. Cloudflare — 1.1.1.1 DNS 캐시 최적화로 메모리 100TB 절감

**요약**
클라우드플레어가 공개 DNS 리졸버 1.1.1.1의 캐시 구조를 최적화해 전체 인프라에서 약 100테라바이트의 메모리를 절감한 과정을 기술 블로그로 공개했다. HN 474점, 댓글 131개로 이날 최상위권.

**왜 눈여겨볼지**
"모델을 더 붙이자"가 기본값이 된 시대에, 자료구조와 메모리 레이아웃을 다시 들여다보는 것만으로 얻는 이득이 여전히 크다는 사례다. 대규모 트래픽 서비스의 캐시 설계 패턴 자체가 좋은 교재다.

📄 링크: https://blog.cloudflare.com/dns-cache-memory-optimization-1111/

## 2. "Small Models Have Arrived" — 작은 모델의 실전 진입

**요약**
소형 언어모델이 실제 프로덕션 워크로드에서 충분한 성능을 내기 시작했다는 주장을 정리한 글. HN 423점, 댓글 189개.

**왜 눈여겨볼지**

📄 링크: https://calv.info/small-models-have-arrived

## 4. "vibecoded fuzzer"로 FFmpeg의 0으로 나누기 버그 발견

**요약**
AI로 대충 짜낸 퍼저(fuzzer)로 FFmpeg에서 division-by-zero 버그를 찾아 이슈로 등록한 사례. HN 165점, 댓글 126개.

**왜 눈여겨볼지**
LLM의 실질적 생산성이 "코드를 대신 써주는 것"보다 "테스트 하네스·퍼저·프로퍼티 테스트를 싸게 만들어주는 것"에서 먼저 나타난다는 관찰. 반대로 오픈소스 메인테이너에게 AI 생성 이슈가 부담이 된다는 반론도 댓글에서 활발하다.

📄 링크: https://code.ffmpeg.org/FFmpeg/FFmpeg/issues/24290
