## 1. 디자인 맥락 정하기

설계 문서에는 사용자, 사용 맥락, 접근성 기준이 이미 있었다. 정해지지 않은 것은 감정적인 톤과 Montage에서 얼마나 벗어날지였다.

| 질문 | 결정 |
|---|---|
| Montage에서 얼마나 벗어날지 | **기반 유지 + 개성 층.** 컴포넌트·토큰·다크 모드는 Montage를 쓰고, 제호·헤드라인 타이포·카테고리 표현 같은 정체성 요소만 직접 디자인한다 |
| 톤 | 글로 고르기 어려워서 시안 4종을 만들어 비교했다(아래 2절) |
| 피할 것 | 마찬가지로 안티레퍼런스 4종을 그려서 확인했다 |

## 2. 톤 시안 비교

시안에는 모두 10월 8일 실제 브리핑을 넣었다.

| 시안 | 핵심 | 판단 |
|---|---|---|
| A · 차분한 지면 | 세리프 제호, 이중 괘선, 제N호, 번호 목차, 괘선으로 연 말씀 | **구조 채택.** 글이 본체인 앱과 맞고 새 데이터가 필요 없다. 다만 세리프 헤드라인과 회색 요약은 D보다 덜 읽혔다 |
| B · 빠른 대시보드 | 시장 지표 4칸, 오늘의 신호, 읽는 시간, 할 일 체크 | 제외. 투자 상세와 겹치고, 표 파싱에 기대야 하며, AI 대시보드 쪽으로 넘어가기 쉽다 |
| C · 따뜻한 루틴 | 인사말, 읽은 정도 막대, 읽는 순서 경로 | 제외. "한로예요" 같은 인사는 매일 쓸 재료가 아니다. 읽음 표시는 나중에 따로 붙일 수 있다 |
| D · 단정한 앱 | 지금 구조를 Montage 그대로 다듬음 | **가독 채택.** 다만 단독으로는 "밋밋한 템플릿"에 가깝다 |
| **E · A 구조 + D 가독** | A의 지면 문법 + D의 고딕 타이포 | **최종 채택** |

안티레퍼런스(같은 데이터로 그림): 뉴스 포털, AI 대시보드 클리셰, 밋밋한 템플릿, 과한 장식. 네 가지 모두 피하기로 했다.

### E안 규칙

- **세리프(Hahmlet)는 짧고 개성이 필요한 곳에만 쓴다.** 제호, 지면 번호, 날씨 기온, 말씀 본문. 헤드라인·요약·본문 같은 읽는 문장은 Pretendard.
- 헤드라인: Pretendard `heading2`(20px) 굵게, 행간 1.5.
- 지면 요약: `body1-reading`(16px) medium, `label.normal`, 2줄 말줄임.
- 헤드라인 아래에 "○○ 전문 읽기 ›" 텍스트 링크를 둔다. 블록 전체가 링크라 버튼을 따로 두지 않는다.
- 지면 행은 화살표 없이 눌림 배경(`fill.alternative` → 누르면 `fill.normal`)으로 피드백한다. 행은 실제 링크(`<a>`).
- 금지 패턴: 왼쪽 굵은 세로선 강조. 기존 말씀 블록과 상세 인용 블록에서 걷어냈다.

### 시안과 달라진 점

1. **호수가 제100호가 아니라 제99호.** 7/1 이후 브리핑이 없는 날이 하루 있다. 날짜 차이가 아니라 실제로 나온 브리핑 수로 센다.
2. **종이 톤 배경(#FBFAF8)은 넣지 않았다.** Montage 컴포넌트는 배경색을 JS 테마 값(hex)으로 직접 칠한다. CSS 변수만 바꾸면 탭·표 고정 칸 등에 흰 조각이 남는다. 차이도 약 2%라 흰 배경을 유지했다.
3. ~~오늘 탭 말씀의 출처("시편 62:5–6")는 빠졌다.~~ (2026-10-11 정정) 10/8이 예외였다. 53일 중 50일은 원문 인용 안에 출처가 있어 요약에 이미 함께 나온다. 문제는 출처가 본문과 같은 세리프로 이어 붙는 것이다(7절 9번).

## 4. 내 위치 날씨 (W3안)

### 왜 앱에서 직접 받나

브리핑은 10시쯤 도착하는데, 출근길에 여는 건 8시쯤이다. 스케줄러가 브리핑에 날씨를 쓰면 정작 필요한 순간에는 어제 날씨를 보게 된다. 그래서 앱이 열릴 때 예보를 직접 받는다.

### 시안 비교

| 시안 | 모양 | 판단 |
|---|---|---|
| W1 · 한 줄 날씨란 | 호수 줄 아래 "동 · 기온 · 최저/최고 · 비" 한 줄 | 가장 조용하지만 하루 중 변화를 모른다 |
| W2 · 제호 옆 날씨 귀 | 신문 제호 옆 테두리 박스 | 지면 콘셉트와 가장 잘 맞지만 정보가 적다 |
| **W3 · 출근·점심·퇴근** | 8시·12시·18시 세 칸 | **채택.** 무엇을 입고 우산을 챙길지 바로 판단된다 |

### 동작 규칙

| 항목 | 규칙 |
|---|---|
| 위치 권한 | 앱을 열 때 묻지 않는다. "내 위치 날씨 보기 ›"를 누를 때만 묻는다 |
| 위치 저장 | 좌표와 동 이름을 localStorage(`weather:v1`)에 둔다. 이후에는 바로 보여준다 |
| 위치 갱신 | 권한이 이미 허용돼 있으면 열 때 조용히 다시 확인한다. 약 1km 이상 움직였을 때만 동 이름을 다시 찾는다 |
| 예보 갱신 | 받은 지 30분이 지났을 때만 다시 받는다 |
| 내일로 전환 | KST 19시부터는 내일 예보. 위 줄에 "내일"이 붙는다 |
| 칸의 비 표시 | 비 확률 30% 이상이면 하늘 대신 "비 60%" |
| 조언 | 비 50% 이상 → "우산 챙기세요", 일교차 10° 이상 → "일교차 N° · 겉옷 챙기세요", 둘 다 → "우산·겉옷 챙기세요" |
| 권한 거절 | 서울 기준 + "위치 권한이 꺼져 있어 서울 기준이에요 · 다시 시도" |
| 위치 실패 | 서울 기준 + "위치를 찾지 못해 서울 기준이에요 · 다시 시도" |
| 오프라인 | 마지막 예보를 "오프라인 · HH:mm 기준"과 함께 보여준다 |
| 받은 적 없이 실패 | 날씨 영역을 숨기고 브리핑만 보여준다 |

### 외부 서비스와 개인정보

- 예보: [Open-Meteo](https://open-meteo.com) `/v1/forecast`. 무료, 키 없음.
- 동 이름: BigDataCloud `reverse-geocode-client`. 무료, 키 없음. 실패하면 "내 위치"로 표시한다.
- 두 서비스 모두 좌표를 소수 둘째 자리(약 1km)로 줄여 보낸다. 위치는 서버에 저장하지 않고 이 기기에만 둔다.

### 1번: 도착 시각

- `build-data`가 `git log --name-only -- 0*/*.md`에서 **날짜별로 그날 브리핑 파일이 처음 커밋된 시각**을 뽑아 `index.json` 날짜마다 `arrivedAt`으로 넣는다(`parseArrivals`).
- 오늘 탭 제호 아래는 "10:08 도착"으로 표시한다. 오프라인이면 "오프라인 · 10:08 도착"이다.
- `generatedAt`은 그대로 둔다. 검색·모아보기의 캐시 키이고([Search.tsx](../app/src/routes/Search.tsx), [Collect.tsx](../app/src/routes/Collect.tsx)), 설정의 "마지막 업데이트"가 쓴다. 뜻을 바꾸면 앱 배포 뒤 바뀐 검색 파일을 다시 받지 않게 된다.
- 배포 체크아웃을 `fetch-depth: 0`으로 바꿨다. 얕은 체크아웃에서는 첫 커밋이 모든 파일을 추가한 것처럼 보여 조용히 틀린 시각이 나온다. 그래서 얕으면 시각을 비우고 경고만 남긴다(틀린 시각보다 없는 편이 낫다).
- 확인: 102일 모두 시각이 잡혔고, 날짜와 다른 날로 잡힌 경우 0. 최근 4일(10:07·10:09·10:08·10:11)이 배포 기록과 같다.

### 4번: 검색 미리보기의 표

- `toPlain`이 표의 구분 줄과 머리행을 빼고, 칸을 " · "로 잇는다. 행은 남기므로 "코스피 6,625.93" 같은 숫자 검색은 그대로 된다.
- `toPlain`은 핵심 문장 추출에도 쓰여, 앞으로 요약에 표가 섞이는 것도 막는다(지금은 0건).
- 확인: 검색 문서의 표 문법 159개 → 0개. 테스트 4개 추가(표 변환 2, 실제 투자 파일 전체, 도착 시각 파싱). 68 → 72.
- 검색 파일 4개의 내용이 바뀌어 이름(해시)도 바뀌므로, 배포 직후 한 번은 다시 받는다.

### 2+3번: 아침 안내 정리

- 본문에 따로 있던 "오늘 브리핑은 10시쯤 도착해요" 줄을 없애고, 호수 줄 오른쪽에 합쳤다.
  - 10:30 전: "제102호 ··· 오늘 브리핑 10시쯤 도착"
  - 10:30이 지나도 없으면: "오늘 브리핑 아직 없음"
  - 오늘 것이 있으면: "10:08 도착"
- 헤더의 "어제 브리핑" 배지는 남겼다. 지금 보는 게 어제 것이라는 다른 사실을 알려준다.
- 날씨 줄은 항상 "오늘"이나 "내일"을 붙인다(예: "역삼1동 · 오늘 이슬비 · 비 74%"). 아침에 어제 브리핑 아래 오늘 날씨가 붙어도 헷갈리지 않는다.
- 측정(08:00 KST, 390×844, 설치 앱): 헤드라인 342 → 308px, 첫 지면 행 563 → 529px. 다 보이는 지면 줄 수는 2줄 그대로이고, 3번째 줄이 34px 더 드러난다.
- 주말 칸 이름(2-1)은 이번 범위에서 뺐다.

### 9·6·10번: 글자 다듬기 (2026-10-12)

- **9 말씀 출처.** `splitCitation`([briefing-text.ts](../app/src/briefing-text.ts))이 요약 끝의 출처를 뗀다. 오늘 탭에서 본문은 세리프, 출처는 그 아래 작은 고딕(`metaColor`)으로 둔다. 상세 말씀 인용 안의 "— 잠언 25:11" 줄도 같은 모양이다(`isCitationLine`).
  - 원문 출처 형식은 세 가지다: "— 잠언 25:11", "— 시편 37편 5절"(장·편·절), "(골로새서 3:23, 개역개정)"(괄호). 처음 규칙은 첫째만 알아봐서 53일 중 34일만 분리됐다. 셋 다 처리해 **51일** 분리. 나머지 2일(10/6, 10/8)은 요약에 출처가 없는 날이다.
  - 상세: 대시로 시작하는 원문 줄 46개 중 출처 45개를 알아본다. 남은 1개는 "사후 작성" 안내 문장이라 출처가 아니다.
- **6 상세 제목.** `splitTitle`이 "국내·경제 브리핑 — 2026-10-09 (금, 한글날)"을 "국내·경제 브리핑"과 그 아래 작은 "한글날"로 나눈다.
  - 날짜 형식은 ISO와 "2026년 7월 3일" 두 가지다. 요일은 "금", "일요일", "주일"로 쓰였다.
  - 형식이 다른 제목("개발자 브리핑 (GitHub Trending / HN / AI 코딩 도구)")은 원문 그대로 둔다.
  - 실제 제목 554개 모두 이름이 비거나 날짜가 남지 않는 것을 테스트로 확인한다.
- **10 자간.** "오늘의 지면/말씀" 머리글 0.1em → 0.04em.
- 테스트 72 → 86.
- 발견(이번 범위 밖): 말씀 원문이 인용 바로 뒤에 `---`를 두는 날은 인용 아래 괘선과 구분선이 두 줄로 겹쳐 보인다(예: 9/21).
